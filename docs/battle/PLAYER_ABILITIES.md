# Player techniques and skills

Derived inventory for [#88](https://github.com/TusanHomichi/PSIV/issues/88).
Engine, capture and route/learner columns are generated by
`python3 -m oracle.sweep.player_abilities --update-doc`. Definitions come from
the ignored pack through psiv-data. Learners come from `generated/characters.json`
and `progression.json`, bounded by a completed route's chapter snapshots.
The source chain includes effect and animation dispatch. Rows without a learner
in the decoded starting/progression tables say so; an `observed L…` learner is
a grant present in a route checkpoint, not an asserted level-up requirement.

## Source and capture method

`oracle.sweep.player_chains` follows `AbilityEffectsOffs`,
`CharTech_TechObjsOffs` and `CharSkill_SkillObjsOffs`, then resolves object ids
only through `BattleObjsGroup*Ptrs`. Event tables reuse those numeric ids and
must never be accepted as battle animation dispatch. The negative control
places an unrelated event at the same id and rejects duplicate battle objects.
Definitions and signed equipment bonuses come from the ignored decoded pack;
no new runtime ability table is copied into source.

`oracle.sweep.player_capture` calls `oracle.force --party-script` for explicit
cases. Party substitutions and resource/status fixtures are declared RAM
patches; they are isolated battles, not an earned campaign route. Replay start
records come from a hashed stock-host RAM dump, checked against live log cells.
The independent stock rerun must have the same log hash. Resumed extraction
checks all five evidence hashes and rejects changed commands or captures.
Actual executed party actions determine capture status, not selected commands.
The JSON inventory records the fixture, round and start frame.

The extractor closes actions before the observed `$1C -> 6` round-tail
transition (`loc_5366`, ps4.asm:7596-7602). Wake calls belong to the round,
never to a skipped enemy whose id remains in `battle_actor`. Replay still
requires the exact complete RNG stream and final HP, TP, status, battle stats,
resistance/shadow bytes, equipment and skill uses. `divergences.json` is not a
waiver for these captures.

Winning-round state is sampled at the observed primary victory routine `$18`
(`loc_66B8`, ps4.asm:9760-9772), after death objects finish and before the
separate reward sequence. `Battle_CheckItemDrop` (4831-4850) must not become
a round-command inventory change. The negative control retains later inventory
writes when no victory boundary is observed.

## Gameplay corrections

- **CROSSCUT and DBLSLASH calculate damage once per target.** The brief's
  two-roll assumption and the previous Crosscut implementation were wrong.
  Crosscut's two scheduled `loc_3B684` passes (ps4.asm:77168-77226) reach
  `loc_9848` through action-table index 7 (15254-15277); that sets fighter
  routine 5, the damage *shake* (14964). `loc_9880` sets routine `$C` once
  (14997-15013), reaching `Fighter_TakeDamage -> loc_2836 -> loc_266C`.
  DblSlash's claw passes (74862-74946) likewise call
  `CloseRangeObjs_DoDamage` (71102), which schedules routine 5.
  Real-owner Prophallus and two-Bal-Duel captures independently show 16 damage
  draws for each skill. DISRUPT shows 16 per enemy, 32 for the two Bal Duels.
- **Animation RNG is gameplay RNG.** NAZAN's parent/child scheduling
  (`loc_388B6`, `loc_388DC`, ps4.asm:73482-73504,73594-73613), gravity
  child delays (73770-73817), MEGID's fourteen child coordinates
  (`loc_38DF8` / `BattleObj_MegidChild`, 73894-73908,73942-73959),
  LEGEON's sixteen particle-coordinate draws
  (75540-75573), and POSIBOLT's twelve trailing coordinates (75931-75970)
  remain in the shared stream, in their source order.
- **FEEVE retains the US byte-selector bug.**
  `AbilityEffect_ElementResistanceUp` (ps4.asm:9265-9276) adds the decoded
  selector to stats `$2E` without doubling. FEEVE changes the water shadow
  byte `$39`, not the live psychic resistance. Recasting writes 1 again.
- **AROWS clears stored-roster sleep globally.** `loc_39494`
  (ps4.asm:74439-74448) clears bit 3 across all eleven character records,
  including off-party and dead/android records, without restoring agility.
  A core event lets the session apply that operation to its owned roster.
- **Recovery tails are distinct.** REVER/REGEN restore AGI/DEX and retain
  only technique sealing (`loc_395A4`, ps4.asm:74502-74533). MEDIC PW heals
  and clears its human recipients, including downed humans, without an
  AGI/DEX reset (78736-78761). ATARAXIA writes TP via `loc_2F40`
  (4649-4656), then clears bit 3 for every occupied party fighter, including
  androids excluded from the TP range (`loc_3CB70`, 78878-78886).
- **SEALS uses the existing enemy AI predicate.**
  `EnemyAI_TechSealed` (ps4.asm:22203-22210) checks the acting enemy's bit 4
  and chooses its decoded conditional ability. It is not a blanket rejection
  of every enemy ability. The sealed-caster capture checks the resulting turn.
  Its DISTORTION fallback was not previously enabled; the shared
  `EnemyAttack_DimensWorm` `$30` arm now reaches `loc_1CC64 -> loc_24BB6`
  (21903-21909,39283-39300,48562-48578). DimensWorm is captured;
  OuterBeast shares that source dispatch and has core controls, not a separate
  stock capture. Other enemy routes remain outside this lane.
- **Group commands preserve the stored aim's retarget draws.**
  `Battle_ComdTechTarget_All` (ps4.asm:2659-2661) leaves the target cell
  untouched. The turn pass still enters `loc_5A98` for ranges 1 through 3
  (8050-8057). SAVOL following VOL therefore takes a tie draw when its stored
  aim is dead, before resolving its unchanged all-enemy range. The shared
  retarget owner handles that for techniques and skills; an explicit negative
  whole-side aim takes no draw.

## Boundaries and verification

The owning regression families are `battle::player_tests`,
`suites::player_abilities`, `session::battle::player_tests`,
`tests.test_player_abilities` and `tests.test_oracle_party_fixture`.
Existing field offerings remain unchanged; `suites::camp_abilities` covers
their learned order, confirmation, costs, caster stat, human/android/dead
eligibility and RNG consumption. No new field surface is introduced.

TP restoration and resistance changes use narration the existing views render.
This lane does not add retail spell art, object timing or a new Godot numeric
overlay; it makes no visual-parity or fresh native-input claim. Those remain
separate presentation work under [#88](https://github.com/TusanHomichi/PSIV/issues/88).
The campaign policy and route are unchanged. The traced release run completes
all 43 chapters in 3,682,524 frames, digest `a4c1d710f4053d81` (the baseline
was `fbe9fef7015aba2e`). It selects CROSSCUT five times and NAGRA nine times.
Those existing commands use the corrected one-pass damage and gravity-animation
RNG, respectively, so the changed digest is expected. This proves the headless
route, not a fresh native-input playthrough.

Local raw commands, failures, hash-bound observations and final check receipts
are retained under `build/p88-evidence/`; the committed fixtures and this
generated inventory are the portable evidence.

The [correction ladder](../AGENT_WORKFLOW.md#correction-ladder) uses rung 1
for shared effect ownership and the exhaustive roster/event path, and rung 2
for observed extraction boundaries, strict replay and inventory negative
controls. Those observations are dynamic cartridge inputs, so their truth
cannot be enforced by a Rust type alone. This lane's review is self-review.
